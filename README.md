# Практична робота №6 — Основи програмування мовою JavaScript

Наскрізний проєкт **AeroHub**. Основна сутність — авіаційна публікація. У роботі створено незалежну від DOM модель даних і чисті функції для майбутньої практичної №7. HTML, CSS і зображення №5 збережені; нові модулі до сторінок поки не підключені.

## Структура і запуск

```text
practical-06/
  package.json
  scripts/
    data.js                    8 навчальних публікацій
    article-service.js         чисті предметні функції
    article-service.test.js    42 автоматичні self-checks
    demo.js                    демонстраційний консольний звіт
  test-results.txt             фактичний вивід перевірок і демонстрації
  README.md
  Звіт_ПР6.docx
  index.html, login.html, register.html, news-form.html, styles/, images/
```

Потрібен **Node.js 18 або новіший**. Залежностей немає; `npm install` не потрібен. Із папки проєкту:

```sh
npm test
npm run demo
```

Альтернатива без npm:

```sh
node scripts/article-service.test.js
node scripts/demo.js
```

`type: module` у package.json вмикає ES Modules. Після успішних тестів автоматично виконується demo; за помилки assert процес завершується ненульовим кодом. Окремий `demo` не запускає self-checks.

## Модель Article

| Поле | Тип | Правило |
|---|---|---|
| id | number | Додатне безпечне ціле число, унікальне в масиві, незмінне після створення |
| title | string | 5–120 символів після нормалізації, відповідно до форми №3 |
| category | string | civil, military, drones або technologies |
| readingTime | number | Ціле число 1–60, хвилини, відповідно до предметної форми |
| isPublished | boolean | true — опубліковано, false — чернетка |

Набір містить чотири категорії, обидва boolean-значення, довгу назву та обидві числові межі 1 і 60. Дані вигадані, без персональних чи конфіденційних відомостей. Усі поля примітивні, вкладених структур у Article немає.

## Нормалізація і валідація

Нормалізація тексту та перевірка допустимості розділені. Категорія обрізається та переводиться в нижній регістр; у назві прибираються крайові й повторні пробіли, табуляція та перенесення рядків. Числа й boolean не перетворюються неявно: рядок `"5"` не є readingTime, рядок `"false"` не є boolean.

| Функція | Результат і контракт |
|---|---|
| normalizeTitle(value) | Нормалізований рядок; для не-рядка — `""` |
| normalizeCategory(value) | Обрізаний lowercase-рядок; для не-рядка — `""` |
| normalizeArticle(input) | Новий об’єкт із чотирма полями payload; `TypeError` для null/масиву/не-об’єкта |
| validateArticle(input) | `{ isValid, errors }`; errors — повідомлення за полями, для не-об’єкта errors.input; не друкує й не змінює input |
| createArticle(input, id) | Новий нормалізований Article; явний аргумент id має пріоритет, зайві поля input не переносяться |

При некоректному id `createArticle` кидає `TypeError`; при помилках полів — `ArticleValidationError` із копією `errors`. Caller може передати ці повідомлення в інтерфейс №7. Довжина визначається стандартною JS-властивістю string.length; для навчальних українських назв цього достатньо, окремий підрахунок графем не реалізований.

## Пошук і перетворення

Усі функції колекцій приймають `data` аргументом і не імпортують глобальний масив із data.js. Невалідний dataset відхиляється: не-масив/некоректний id — `TypeError`, поля запису — `ArticleValidationError`, повторний id — `RangeError`.

| Функція | Результат |
|---|---|
| findArticleById(data, id) | Об’єкт-джерело або `undefined`, якщо коректний id не знайдено |
| filterArticles(data, criteria = {}) | Новий масив; дозволені category, isPublished і query, умови об’єднуються через AND |
| sortArticlesByTitle(data, direction = "asc") | Копія масиву, localeCompare з локаллю uk; asc/desc, за однакових назв додатково id |
| sortArticlesByReadingTime(data, direction = "asc") | Копія масиву за числовим часом; за рівного часу додатково id |
| toArticlePreview(article) | Новий короткий об’єкт: id, title, categoryLabel, readingLabel, isPublished |
| getArticlePreviews(data) | Масив таких представлень через map |
| summarizeArticles(data) | total, published, drafts, totalReadingTime, byCategory, averageReadingTime; середнє округлене до 2 знаків |
| hasDrafts(data) | some: чи є хоча б одна чернетка |
| everyArticlePublished(data) | every: чи всі записи опубліковані |

Текстовий query нормалізується та порівнюється без урахування українського регістру. Порожній query повертає всі записи. Відсутність збігів у фільтрі дає `[]`; невідома категорія/напрям сортування — `RangeError`, неправильний тип критеріїв чи невідомий ключ — `TypeError`. Це допомагає відрізнити помилку виклику від порожнього результату.

## Агрегація й порожні масиви

`reduce` починає з нульових лічильників та окремого об’єкта чотирьох категорій. Для `[]` повертаються нулі, середнє дорівнює 0 без ділення на нуль; find дає undefined, filter/map/sort — нові порожні масиви. `hasDrafts([]) === false`; `everyArticlePublished([]) === true` — стандартна логіка every для порожнього набору, а не ознака наявності матеріалів.

Перевірений підсумок data.js: **8 записів, 6 опублікованих, 2 чернетки, 118 хв загалом, 14.75 хв у середньому**. Кожна категорія містить 2 записи. Фільтр `{ category: "technologies", isPublished: false }` повертає id=7.

## Незмінюваний CRUD

| Функція | Успіх | Помилка |
|---|---|---|
| addArticle(data, newArticle) | Новий масив через spread; новий запис нормалізовано й скопійовано | Повторний id — RangeError; невалідні поля — ArticleValidationError |
| updateArticle(data, id, changes) | Новий масив через map та новий об’єкт через spread; решта записів спільна за посиланням | Відсутній id — RangeError; поле id чи будь-який невідомий ключ у changes — TypeError; невалідні поля — ArticleValidationError |
| removeArticle(data, id) | Новий масив через filter | Відсутній id — RangeError |

Навіть `{ id: поточнийId }` у changes заборонено. Порожній changes дозволений і повертає новий масив та копію цільового запису. Операції не мутують джерело. Це поверхневі копії: незмінені об’єкти й результати find/filter/sort зберігають посилання на записи джерела; caller не повинен змінювати їх напряму. Для вкладених даних у майбутньому потрібне окреме копіювання.

## Self-checks і результат

**42/42 PASS**, код завершення 0. Перевірено:

- нормалізацію пробілів, регістру та некоректних текстових типів;
- валідні/невалідні записи, null, масиви, назви довжиною 4/5/120/121;
- час 1/60, а також 0/61, дроби, NaN, Infinity, рядок замість числа;
- коректне значення false, захист від категорії __proto__, дублікатів і небезпечних id;
- знайдений перший запис, відсутній id, фільтри з результатом і без нього;
- map/labels, reduce на наборі та `[]`, some/every;
- український порядок А, Г, Ґ, Е, Є та числове сортування;
- add/update/remove, заборону зміни id і невідомих полів;
- незмінність джерела: масив і його записи заморожені через Object.freeze, додатково порівняно JSON-знімок.

Жодної помилки під час фінального запуску не залишилося. Перевірки зафіксували очікувані граничні контракти: false не губиться; індекс першого запису не перевіряється як boolean; для порожнього набору немає NaN; sort працює з копією; id не можна підмінити через spread changes.

Фактичний вивід збережений у test-results.txt. У сервісі немає console.log або DOM-звернень. Вивід зосереджений у demo.js і тестовому runner. У №7 можна повторно використати createArticle, filterArticles, getArticlePreviews, summarizeArticles та CRUD, додавши окремий DOM-шар.
